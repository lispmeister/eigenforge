System Design

Eigenforge V1 is an Elixir umbrella with strict authority boundaries. Contracts provide shared message shape and signing helpers; IO owns the outside-world boundary; core owns decision authority and its local SQLite ledger; mailbox routes immutable envelopes; dashboard reads state only.

Application Responsibilities

eigenforge_contracts

Owns schemas, generated modules, canonical JSON, hashing, HMAC signing, verification helpers, and golden trace display maps.

Does not own: runtime authority, IO, delivery, dashboard rendering, or local ledger writes.

eigenforge_io

Connects to Home Assistant or simulator, normalizes observations, publishes streams, verifies envelopes, executes valid commands, and logs IO fault/status locally.

Does not own: decisions, policy, core SQLite writes, or after-action truth.

eigenforge_core

Owns the OODA loop: validate live input, run reasoner, check capability and policy, finalize decisions, write the local SQLite ledger, issue signed envelopes, and interpret after-action evidence.

eigenforge_mailbox

Accepts, stores, routes, and delivers immutable messages. It may create mechanical delivery receipts after the corresponding local ledger commit.

Does not own: signature validation, authorization, payload enrichment, or policy.

eigenforge_dashboard

Read-only Phoenix LiveView showing active IO mode, sensor state, fan state, decisions, recent ledger events, and IO faults/status.

Consensus And Local Persistence

Each core node owns a local SQLite database. V1 treats the single core as a one-member consensus group; V2 replaces that boundary with three-core quorum while preserving the same rule: finalize first, persist locally, then command IO.

V1 Persistence

one core node single-core finalized SQLite WAL mode append-only triggers

Core stores finalized OODA facts only: reasoner outcomes, capability checks, policy decisions, command envelopes, relevant faults, and after-action events.

Core Does Not Store

bulk telemetry sensor history actuator history historian charts

Live and historical sensor data stay in Home Assistant, simulator streams, and future historian systems.

Network Split Rule

2-of-3 may finalize 1-of-3 cannot command signed catch-up node-local sequence

After a partition heals, nodes accept only signed finalized decisions with valid quorum evidence.

Message Flow

A command can only cross into IO after core finalizes the decision and commits the relevant event to its local SQLite ledger. IO then verifies both the command envelope and delivery receipt before execution.

Decision Logic

The deterministic V1 reasoner only treats CO2 as control-relevant. Humidity and temperature are observe-only inputs. The fan actuator is idempotent, so stale or unknown fan state may still allow a fan on/off command when CO2 requires action.

Observation Reasoner Outcome Policy / Command
CO2 > 1000 ppm, fan off propose_action fan on Allow if capability grant is valid
CO2 < 500 ppm, fan on propose_action fan off Allow if capability grant is valid
CO2 inside 500..1000 ppm no_threshold_event No physical command
Threshold breached but fan already in requested state propose_no_action No command; durable no-action outcome
CO2 stale, malformed, missing, unavailable, or unknown insufficient_fresh_data Deny; record stale/no-command path
Unknown non-idempotent actuator state Control request may exist Deny blind command

Ledger Integrity

Each core node stores a durable decision/action ledger in local SQLite, not telemetry. Live observations remain in Home Assistant, simulator streams, and future historian systems. The ledger records finalized decisions, authorization facts, issued commands, relevant faults, and after-action outcomes.

Ledger Event Type When Recorded
ledger_genesisBefore normal runtime; establishes ledger identity.
connection_status_observedCore observes outside connection state changes.
io_fault_observedFault affects OODA or decision context.
reasoner_outcome_recordedReasoner produces a decision-relevant outcome.
capability_check_recordedCapability grant lookup is evaluated.
policy_decision_recordedPolicy allows, denies, or returns a stub/noop result.
command_envelope_issuedCore persists command envelope before mailbox delivery.
after_action_recordedCore interprets IO observations after command delivery.
stale_snapshot_deniedStale or unsafe live data prevents physical command.
node_fault_observedNode faults and restarts where practical.

Runtime Modes

Home Assistant Mode

EIGENFORGE_IO_MODE=home_assistant

Uses the Home Assistant WebSocket API for state ingest and REST API for fan commands via switch.turn_on and switch.turn_off.

Missing required Home Assistant config or HMAC secret fails startup. Unreachable Home Assistant may start degraded and retry with deterministic capped exponential backoff up to EIGENFORGE_HA_RECONNECT_MAX_MS.

Static config validation is fail-fast; dynamic wrong or missing entities keep the room in degraded no-physical-control mode until observations validate again.

Simulator Mode

EIGENFORGE_IO_MODE=simulator

Uses static normalized snapshot fixtures from config/simulator_snapshots. It must not connect to Home Assistant, InfluxDB, ESPHome, MQTT, or other outside data sources.

Unsigned test/demo fixtures may be allowed, but decisions produced from them are signed and persisted normally.

Shared Settings

EIGENFORGE_HMAC_SECRET signs config, capability grants, receipts, command envelopes, and ledger events.

EIGENFORGE_CORE_NODE_ID and EIGENFORGE_CORE_DB_PATH identify the local core ledger. Command envelopes expire after 5 seconds; snapshots are stale after 15 seconds.

Mailbox And Restart Semantics

Mailbox delivery remains mechanical only. Signed receipts are persisted before publish and phase-tracked as receipt_stored, publish_attempted, and io_accepted.

Receipt-store corruption starts degraded and blocks publish or redelivery until repair. Pending restart recovery classifies work conservatively from persisted UTC deadlines.

Implementation Invariants

These are the design constraints that should survive refactors and V2 migration.
Invariant Reason
Core finalizes and persists before command delivery Durable authority must exist before the outside world changes.
Mailbox routes but does not authorize Delivery must not silently become a second policy path.
IO verifies envelope and receipt before execution Execution boundary rejects invalid, expired, duplicate, or uncommitted commands.
After-action truth is authored by core IO reports observations and faults; core interprets them in the OODA loop.
Ledger is authoritative; projections are rebuildable Local read models can be convenient without becoming control authority.
Non-quorum partitions cannot command Network splits must not create competing actuator decisions.
Signed payloads declare format and schema identity V1 remains inspectable while leaving room for future encoding formats.
