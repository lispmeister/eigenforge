## Decisions

| Decision | Rationale | Consequences / Follow-up |
|----------|-----------|--------------------------|
| Keep Markdown as the carrier format for V1 specs. | The current spec is already repo-native, reviewable, and friendly to AI coding agents. The missing capability is traceability structure, not prose replacement. | Future spec tooling can parse stable IDs and structured blocks from Markdown before requiring a new language. |
| Add stable IDs instead of rewriting the whole spec. | Stable IDs give requirements, contracts, invariants, golden traces, and tickets durable handles. | Future implementation tickets can cite IDs such as `OODA-V1-003`, `PROTO-V1-IDEM`, `AA-V1-001`, and `INV-09`. |
| Treat JSON Schema and golden traces as the executable contract layer for V1. | They already align with the implementation approach and are lighter than adopting SysML, Event-B, TLA+, or FRET as a required authoring tool. | Formal tools remain available for high-risk slices such as recovery, command lifecycle, and later quorum. |
| Split future-facing material into compatibility and deferred classes. | V1 must preserve some V2 shapes, but agents should not mistake those shapes for V1 implementation scope. | Added `COMPAT-V1-*` and `DEFERRED-V2-*` labels to the spec. |
| Add a traceability index to the V1 spec. | The index lets reviewers and agents navigate from intent to requirements, contracts, invariants, and acceptance coverage. | The index should be maintained as future spec IDs and traces are added. |
