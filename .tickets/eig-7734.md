# Spec §10: define or remove the confirmed_already_in_state adapter no-op clause

Spec §10 defines confirmed_already_in_state as applying when 'pre-command fan state was known and already matched the requested state, OR the adapter reports a no-op because the target was already in the requested state.' The second clause has no corresponding fault_type in §6's IoFaultStatusEvent enum (no no-op value), no implementation, and no test. It is currently unreachable by any code path. Either a fault_type must be added and the code path implemented, or the clause must be removed from the spec.

## Acceptance Criteria

PROTOTYPE-V1-SPEC.md §10 is updated to either (a) define the fault_type value for adapter no-op and add it to §6's fault_type enum, with corresponding implementation and test, or (b) remove the adapter no-op clause entirely, making pre-command-state the sole criterion for confirmed_already_in_state. The implementation and spec agree.
